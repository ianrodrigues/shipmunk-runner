# Transferred PHP behavioural coverage

This records where the behavioural intent of the retired PHP setup and native-image tests now lives in the Go suite, scenario by scenario, so the removal in this change is auditable rather than assumed. It does not re-list PHP coverage that other Go packages already absorbed before this change (contracts, protocol parsing, sandbox isolation, process-death recovery, credential handling and patch collection); that mapping already lived in `docs/go-transition.md` and remains true. Every Go test named below was run against a real Docker engine and the real pinned native image as part of this change, not merely read.

| PHP test file | Scenario | Go coverage |
| --- | --- | --- |
| `runner/tests/SetupTest.php` | Rejects setup bundles whose `base_url` carries userinfo, control characters, a query token, a fragment, a non-loopback `http://` scheme or a `file://` scheme | `internal/command/cli_test.go` `TestParseSetupBundleValidatesFieldsAndServerOverride` |
| `runner/tests/SetupTest.php` | Rejects an expired bundle, a traversal `profile_id`, a CRLF-injected token, an unsupported `runtime_version` and a non-1 bundle version | `internal/command/cli_test.go` `TestParseSetupBundleValidatesFieldsAndServerOverride` |
| `runner/tests/SetupTest.php` | Accepts a loopback `http://` override for local testing | `internal/command/cli_test.go` `TestParseSetupBundleValidatesFieldsAndServerOverride` (server URL override case) |
| `runner/tests/SetupTest.php` | The setup file is protected to mode 0600 after being read, and a symlinked, hard-linked, directory-redirected or oversized setup file is refused | `internal/command/cli_test.go` `TestRunSetupProtectsSummarizesAndRequiresConfirmation`, `TestRunSetupRejectsUnsafeFilesBeforeDisplayingBundle` |
| `runner/tests/SetupTest.php` | Renewal refuses a changed server/profile identity or an older installed release, without mutating the existing installation | `internal/command/cli_test.go` `TestRunSetupBlocksRenewalBeforeInstallingRelease` |
| `runner/tests/SetupTest.php` | An unreachable or redirecting/oversized server health check fails setup before any file is written | `internal/command/setup_launch_test.go` `TestSetupServerHealthRefusesRedirectsAndFailures`, `TestSetupServerHealthRejectsOversizedResponse`, `TestSetupPreflightFailuresPreserveConfiguration` |
| `runner/tests/SetupTest.php` | Connection/operation identifiers are fresh lowercase ULIDs | dropped: obsolete. Client-side operation-ID generation moved to the installed `connect` launcher only (`internal/command/setup_launch_test.go` `TestInstalledLaunchersDispatchOnlyBoundArguments` asserts a fresh 26-character ID per invocation); the raw connect/probe/disconnect flag parser now requires the caller to supply a canonical ULID, validated by `TestParseProfileOptionsRequiresCanonicalIdentifiers` |
| `runner/tests/SetupTest.php` | An unreachable-server exception message never leaks the dialed host | dropped: obsolete. `RunSetup` prints one fixed diagnostic string for every health-check failure and never interpolates the underlying network error, so there is no code path left that could leak a host |
| `runner/tests/SetupContextTest.php` | Docker's real build context for the native image excludes a checkout's `.env` and setup-token files while keeping the two runtime assets the image needs | `internal/profile/native_image_docker_test.go` `TestNativeImageDockerfileContextExcludesCheckoutSecrets` (new) |
| `runner/tests/SetupImageTest.php` | Two builds from different checkouts produce distinct, immutable image identities | dropped: obsolete. `buildSetupImage` always resolves the image identity from Docker's own `--iidfile` content digest, so distinct content necessarily yields distinct IDs by Docker's own addressing, not by application logic that could regress silently |
| `runner/tests/SetupImageTest.php` | Restarting the installed runner reuses the originally built image rather than rebuilding one | `internal/command/setup_launch_test.go` `TestInstalledLaunchersDispatchOnlyBoundArguments` (asserts `--image=`/`--repository-image=` carry the persisted `image_id` from `config.json`) |
| `runner/tests/InstalledNativeImageTest.php` | Assets extracted from the installed release are private | The Go installer keeps each manifest file's own mode (0644/0755, asserted by `internal/release/release_test.go`'s `TestBuilderProducesDeterministicClosedPlatformRelease` and neighbours) and instead enforces privacy at the directory level: every release directory must be mode 0700 and owned by the installing user (`protect` in `internal/install/install.go`, enforced through `ensurePrivateDirectory` and `verifyRelease`), refusing to serve a release under a world- or group-readable directory. `internal/install/install_test.go`'s `TestInstallRejectsReleaseDirectoryWithUnsafeMode` (new) covers that directory-mode rejection. |
| `runner/tests/InstalledNativeImageTest.php` | The built image bakes the MCP/schema assets at `/usr/local/lib/shipmunk` with mode 755 (directory) and 644 (files), owned by root, and they stay readable to the unprivileged agent user under full container hardening | `internal/profile/native_image_docker_test.go` `TestNativeImageBakedAssetsAreReadableByUnprivilegedUser` (new) |
| `runner/tests/NativeImageTest.php` | The image's default OpenSSL trust store trusts the real Mozilla root and rejects an explicitly untrusted one | `internal/profile/native_image_docker_test.go` `TestNativeImageTrustStoreAndPinnedVersions` (new) |
| `runner/tests/NativeImageTest.php` | The codex/claude CLI `--version` output exactly matches the pinned runtime versions, under network-none/read-only/non-root isolation | `internal/profile/native_image_docker_test.go` `TestNativeImageTrustStoreAndPinnedVersions` (new), reusing the already-unit-tested `PinnedVersion`/`Command`/`VersionMatches` in `internal/profile/native_test.go` |
| `runner/tests/NativeHomeTest.php` | Native home ownership and permissions are normalized after the container stops | `internal/profile/runtime_docker_integration_test.go` `TestDockerRuntimePreservesLinuxOwnershipAndNormalizesAfterStop` |
| `runner/tests/NativeHomeTest.php` | A foreign (root-written) native entry is rejected without any mutation | `internal/profile/runtime_docker_integration_test.go` `TestDockerRuntimeRejectsForeignOwnedNativeEntryWithoutMutation` |
| `runner/tests/NativeHomeTest.php` | Host credentials/configuration never enter the native container's environment | `internal/profile/runtime_docker_integration_test.go` `TestDockerRuntimePreservesLinuxOwnershipAndNormalizesAfterStop` (synthetic secret environment variables asserted absent from the container-visible environment) |
| `runner/tests/NativeHomeTest.php` | The real pinned Codex CLI reproduces a specific generated metadata file (`installation_id`) at mode 0644 after a preflight run | dropped: obsolete. This is vendor CLI behaviour, not Shipmunk logic; the Go normalization tests above already prove arbitrary native-tree paths are protected and foreign entries rejected regardless of which files a given CLI version happens to create |
| `runner/tests/CodexExclusionTest.php` | An uncertain cleanup quarantines the execution reservation and blocks every profile lifecycle operation (login/probe/disconnect) until it is resolved | `internal/profile/lifecycle_test.go` `TestLifecycleRejectsExecutionOverlapAndCompletedReplay`; `internal/profile/store_test.go` `TestExecutionJournalUsesPHPIdentityAndRequiresLock` |
| `runner/tests/CodexExclusionTest.php` | Restart retains an uncertain execution reservation, then confirms cleanup normalizes the home and acknowledges the stopped attempt | `internal/command/codex_executor_test.go` `TestProfileExecutorRetainsReservationUntilCleanupSucceeds`; `internal/supervisor/supervisor_test.go` `TestCompositeCleanupFailureRetainsJournalAndPreventsAcknowledgement` |
| `runner/tests/CodexExclusionTest.php` | Restart refuses a newer/duplicate reservation before cleanup and never clears the journal early | `internal/profile/store_test.go` `TestExecutionJournalUsesPHPIdentityAndRequiresLock` (duplicate and fence-mismatched reservation rejection) |
| `runner/tests/CodexExclusionTest.php` | An unsafe entry left in the native home keeps the reservation durably quarantined even though the process exited cleanly | `internal/profile/store_test.go` `TestReleaseExecutionRetainsReservationWhenHomeIsUnsafe` (new) |
| `runner/tests/CodexExclusionTest.php` | Rejected pre-authorization leaves no reservation; a recovery journal missing its profile identity is refused rather than guessed at | `internal/command/codex_executor_test.go` `TestProfileExecutorRejectsMismatchedCredentialBeforeSideEffects`; `internal/attemptstate` current-format journal tests (unchanged by this change) |
| `runner/tests/CodexExclusionTest.php` | A claim-validation failure after the profile reservation is taken still releases it and acknowledges the stopped attempt | `internal/supervisor/supervisor_test.go` `TestClaimPersistenceFailureAcknowledgesWithIndependentBoundedContext`; `internal/command/codex_executor_test.go` `TestProfileExecutorReservesCleansAndReleases` |
| `runner/tests/CodexExclusionTest.php` | A busy profile preserves durable attempt recovery for a later restart to reconcile, without acknowledging or touching the profile it could not enter | `internal/command/codex_runner_test.go` `TestCodexProfileRouterExecuteFailsWhenProfileIsBusy` (new); `internal/supervisor/supervisor_test.go` `TestUncertainCreationRetainsReservationWithoutAcknowledgement` |
| `runner/tests/CodexExclusionTest.php` | Malformed profile identities are rejected without persisting unrecoverable attempt state | `internal/command/codex_runner_test.go` `TestCodexProfileRouterRejectsMalformedProfileIdentity` (new) |
| `runner/tests/CodexExclusionTest.php` | A failed stopped-acknowledgement retries safely after release, and still refuses a newer reservation while unresolved | `internal/supervisor/supervisor_test.go` `TestAmbiguousClaimPersistenceRetainsJournalWhenAcknowledgementFails`; `internal/profile/store_test.go` `TestExecutionJournalUsesPHPIdentityAndRequiresLock` |

`runner/tests/CodexExclusionTest.php` composed all nine scenarios above through one PHP `Supervisor` wired directly to a real `CodexSandbox`. The Go side proves the same behaviour compositionally: `internal/supervisor` owns the generic claim/journal/acknowledgement machinery independent of profiles, `internal/profile` owns reservation exclusivity and fencing independent of the supervisor, and the two new `internal/command/codex_runner_test.go` tests close the one piece of glue between them, at the router, that PHP tested only through the full integration and Go had not tested at all before this change.
