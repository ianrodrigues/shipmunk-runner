# Release packaging and application pins

Go release builds inject the exact validated release tag into every operational binary. Both commands—`shipmunk-runner` (setup, connect, probe and run subcommands) and `shipmunk-watchdog`—must print that tag through `--version`; unversioned local builds print `development`. The supported artifact matrix is Linux and Darwin on `amd64` and `arm64`. Cross-compilation establishes artifact availability, not successful live operation: Linux remains the required Docker engine, and each host platform still requires its runtime validation. Windows and other architecture tuples are not release targets.

Runtime validation currently differs by platform, and the build matrix does not change to reflect this. `linux-amd64` is smoke-tested in CI in a PHP-free container on every push, installing the packaged release and driving `connect`/`run` with neither PHP nor Go on the container's `PATH`. `linux-arm64` smoke passes locally, under QEMU emulation or native `arm64` hardware, using the same smoke suite's `SHIPMUNK_INSTALL_SMOKE_ARCH` parameter; it is a tested parameter that is not yet wired to a CI runner. `darwin-arm64` native operation was demonstrated by the server's published-runner check against `v0.1.0-alpha.10` on an Apple Silicon host: the release binaries ran setup, a connect probe, and a run flow, but the host was not PHP-free, so this is evidence of native operation rather than a clean-host smoke test. `darwin-amd64` is compile-only and unvalidated; it must not be described as a supported executable platform until a smoke run exists on an Intel host.

Use `make go-build VERSION=v1.2.3` for a local versioned build check. `go run ./cmd/shipmunk-package . dist v1.2.3` builds deterministic USTAR archives for the four supported host tuples. Every archive contains the two compiled commands, the runtime container allowlist, and the license. Members are sorted regular files with fixed metadata, recorded SHA-256 digests, sizes, and executable modes. The measured bounds are 32 MiB per member, 128 MiB per archive, and 16 members. The platform-indexed `runner-release.json` binds every archive URL and closed file inventory and declares Linux `amd64` and `arm64` native-image support. `SHA256SUMS` binds the four archives and manifest.

Release building runs without repository write permission. The upload job receives only the checked workflow artifact and exposes its write token only to the publisher. Publication validates the local checksum inventory and GitHub's recorded asset digests, rejects duplicates or changed bytes, resumes missing uploads, and exposes `runner-release.json` last. The release package command owns semantic-version validation; the Make target only embeds the supplied value while compiling the operational binaries.

The compiled `shipmunk-runner` binary's `setup` subcommand consumes the closed Go platform manifest and matching local archive selected by the server bootstrap. It verifies the archive before installing it in a content-addressed release directory, checks the control plane, builds the allowlisted runtime image with a Linux Docker engine, and activates private configuration, tokens, and minimal `run`, `connect` and `probe` launchers together. The launchers invoke the exact installed `shipmunk-runner` binary by absolute path with the matching subcommand; that binary strictly rebuilds operational arguments from protected configuration. Setup ends by running `connect` itself (unless `--skip-connect` is given) and never starts queued work without a later explicit `run` command.

`setup` exits `0` when installed and (unless skipped) connected, `3` when installed but the connect step did not finish, and `1` for every other setup failure.

Declining the confirmation prompt also exits `0` without installing anything, so automation must not read a bare `0` as proof of an installed, connected runner.

Renewing an installation compares the incoming manifest's release version against the installed `release_version` using semantic-version precedence. The same version renews tokens without changing the release, and a newer version proceeds; an older version is refused by design, and the refusal names both versions in a sanitized message. There is no historical rollback or PHP-state migration for a refused downgrade: publish and pin a newer release instead. Because build metadata never affects version precedence, a same-version renewal additionally requires the incoming archive's SHA-256 to match the installed release's recorded digest, refusing a differently built same-version archive instead of silently replacing the installed release.

The GitHub release workflow listens to `release: published`, which covers stable releases and prereleases, including publication from a draft. Trusted release checks and builds use the existing `github-runner-01` self-hosted Linux runner. The configured job skips fork pull requests rather than routing them to a hosted fallback. Repository approval is required for all external contributors because forks can modify the workflow guard; maintainers must not approve fork workflow execution and instead promote reviewed code to internal branches. The workflow checks the release commit, builds once without write permission, and passes the exact output to the narrowly write-scoped upload job. The release tag supplies the package version and must be a valid semantic version prefixed with `v`; no separate version-file edit is needed. `VERSION` remains the default for legacy local packaging. Release assets are never overwritten with different bytes. Partial uploads can be completed by rerunning the failed job.

`darwin-arm64` now has a host-native PHP-free install smoke: `internal/installsmoke`'s `TestHostNativeInstallsReleaseWithoutPHPOrGo` (`make install-smoke-host-check`) runs the same extract, verify, guided setup, `run --once` and `probe` flow as the linux container smoke, but directly on the host, since only Linux gets a Docker container here. It cannot start from a genuinely clean machine image the way the container can, so instead every subprocess under test runs with PATH scrubbed to the fixture's own bin directory plus `/usr/bin` and `/bin`, and the test asserts inline that neither `php` nor `go` resolves on that scrubbed PATH. This is PATH-scrubbed evidence on a developer Mac, not a clean-machine-image smoke, and it is a manual, opt-in target rather than part of `make check` or CI.

Application adoption of the Go manifest remains explicit. All release metadata is public; operator tokens are never embedded in release assets. Creating a newer runner release does not silently upgrade applications or existing execution hosts, and unavailable pinned bytes must never fall back to a moving branch or unverified package.

The source was fully moved out of the application; runner-coupled application tests are temporarily disabled rather than duplicating source or introducing a Composer dependency. The initial extraction retains the `runner/` prefix and the fixture container paths so its existing standalone tests and Docker contexts remain unchanged. `source-snapshot.json` is provenance for the extraction, not a release signature or live compatibility result.

Cutting a release moves `CHANGELOG.md`'s `## Unreleased` section under a new `## <tag> - <date>` heading before tagging, so the tagged commit already carries the dated section; the GitHub release body then links straight to that section (`CHANGELOG.md#<tag-anchor>`) instead of duplicating its bullets. `make lint` and the `.githooks/pre-push` hook enforce the other half of this: any pull request touching `cmd/` or `internal/` must also touch `CHANGELOG.md` with an operator-facing `Unreleased` line, unless one of its commits carries a `changelog: none` trailer for a change with no operator-visible effect.
