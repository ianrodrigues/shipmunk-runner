# Release packaging and application pins

Go release builds inject the exact validated release tag into every operational binary. All four commands—`shipmunk-runner`, `shipmunk-profile`, `shipmunk-setup`, and `shipmunk-watchdog`—must print that tag through `--version`; unversioned local builds print `development`. The supported artifact matrix is Linux and Darwin on `amd64` and `arm64`. Cross-compilation establishes artifact availability, not successful live operation: Linux remains the required Docker engine, and each host platform still requires its runtime validation. Windows and other architecture tuples are not release targets.

Use `make go-build VERSION=v1.2.3` for a local versioned build check. `go run ./cmd/shipmunk-package . dist v1.2.3` builds deterministic USTAR archives for the four supported host tuples. Every archive contains the four compiled commands, the runtime container allowlist, and the license. Members are sorted regular files with fixed metadata, recorded SHA-256 digests, sizes, and executable modes. The measured bounds are 32 MiB per member, 128 MiB per archive, and 16 members. The platform-indexed `runner-release.json` binds every archive URL and closed file inventory and declares Linux `amd64` and `arm64` native-image support. `SHA256SUMS` binds the four archives and manifest.

Release building runs without repository write permission. The upload job receives only the checked workflow artifact and exposes its write token only to the publisher. Publication validates the local checksum inventory and GitHub's recorded asset digests, rejects duplicates or changed bytes, resumes missing uploads, and exposes `runner-release.json` last. The release package command owns semantic-version validation; the Make target only embeds the supplied value while compiling the operational binaries.

The currently supported installer still consumes the legacy PHP release format until issue #58 completes. `php tools/package.php dist v0.1.0-alpha.1` creates that deterministic archive using the standalone `PackageBuilder`; its 2 MiB archive and 256 KiB member limits apply only to the legacy format.

`runner-release.json` contains `version`, the exact public asset `url`, the archive `sha256`, every included filename's SHA-256 digest, and the separately pinned `installer_url` and `installer_sha256`. `installer.php` combines the existing strict installer class with a small CLI entrypoint; it does not contain another archive implementation. `SHA256SUMS` binds the archive, installer and JSON manifest. The package is independent of Git metadata and source timestamps. The installer validates the complete archive before any extraction, including canonical regular-file headers, a closed path manifest, per-file hashes, zero padding and the exact end marker. Installation creates files exclusively in private staging and rejects unsafe ownership, links or altered existing releases.

The GitHub release workflow listens to `release: published`, which covers stable releases and prereleases, including publication from a draft. Trusted release checks and builds use the existing `github-runner-01` self-hosted Linux runner. The configured job skips fork pull requests rather than routing them to a hosted fallback. Repository approval is required for all external contributors because forks can modify the workflow guard; maintainers must not approve fork workflow execution and instead promote reviewed code to internal branches. The workflow checks the release commit, builds once without write permission, and passes the exact output to the narrowly write-scoped upload job. The release tag supplies the package version and must be a valid semantic version prefixed with `v`; no separate version-file edit is needed. `VERSION` remains the default for legacy local packaging. Release assets are never overwritten with different bytes. Partial uploads can be completed by rerunning the failed job.

After a release succeeds, the application maintainer downloads `runner-release.json`, verifies the published archive, installer and checksums, and commits the exact manifest into `resources/runner-release.json`. The bootstrap uses that reviewed version and both URL/digest pairs. It verifies the installer before executing it, then the installer verifies the archive and the complete file manifest before writing runtime files. All installer arguments are public metadata; operator tokens are not embedded in release assets. Creating a newer runner release does not silently upgrade applications or existing execution hosts. A missing or unavailable pinned release fails setup; it does not fall back to a moving branch or an unverified package.

The source was fully moved out of the application; runner-coupled application tests are temporarily disabled rather than duplicating source or introducing a Composer dependency. The initial extraction retains the `runner/` prefix and the fixture container paths so its existing standalone tests and Docker contexts remain unchanged. `source-snapshot.json` is provenance for the extraction, not a release signature or live compatibility result.
