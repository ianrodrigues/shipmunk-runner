# Go runner compatibility foundation

The Go module is pinned to Go 1.27.1 and uses only the standard library. `make go-check` runs formatting verification, vet, unit tests, the race detector, and local builds of the three operator commands and the independent `shipmunk-watchdog` helper. A failure to build any command fails the build target. `make go-build VERSION=v1.2.3` injects the same release identity into all four commands; without an explicit value they report `development`. Go 1.21 or newer can acquire the pinned version when `GOTOOLCHAIN` permits automatic toolchain selection; older installations cannot bootstrap it this way.

The schema authority is the server's `contracts/v1` at commit `5f258aaa1873aa06e9252881334d8ab90011b415`. Only that immutable schema and synthetic fixture corpus is included here; the private server repository is not a build dependency. [The source inventory](../internal/protocol/contracts-source.json) records the upstream paths and SHA-256 digests, and an integrity test checks every included file. Updating the corpus and its pin is a deliberate compatibility change. The runner embeds the schemas, so HTTP validation does not depend on a checkout or the process working directory.

The upstream positive fixtures prove schema conformance, not executable artifact provenance: their placeholder hashes are not backed by content, and some references reuse an artifact ID with different placeholder hashes. Keep the pinned bytes intact. HTTP download tests instead use real synthetic bytes and their computed hashes; supervision fixtures must provide distinct, consistent artifact identities before testing preparation or execution.

The declared binary targets are Linux `amd64` and `arm64`, plus macOS `amd64` and `arm64`. Linux remains the required Docker engine platform. macOS host support requires validation with a Linux Docker engine, including filesystem ownership and process cleanup; compiling a binary does not establish that support. Windows is not a release target. Release packaging owns the closed platform manifest and must embed its exact validated tag in every binary.

The Go runner now implements the isolated fixture driver and `--driver=codex`, including once/continuous polling, durable attempt recovery, workspace preparation, protected explicit sessions, fenced repository commands, verified patch collection and independent watchdog cleanup for the complete native/repository/collector topology. It also implements `shipmunk-profile` login, probe and disconnect with a protected native profile store, durable operation recovery, renewable leases and credential-only Docker isolation. Verified releases include a compiled setup command that installs the platform archive, builds the pinned runtime image, and creates explicit operational launchers without PHP or a Go toolchain. The dedicated host account's installation directory and `PATH` are trusted configuration: Docker is discovered through that path, so neither may be writable by untrusted accounts or repository processes. The server now pins and installs a verified Go prerelease explicitly for repository-native work; the previously published PHP runner path is obsolete and scheduled for removal. Synthetic profile and execution coverage does not establish live subscription compatibility.

The compatibility map below separates implemented coverage from the remaining port. The PHP reference is runner commit `8b90bcff2519ea86e00e3d76fef22335144081f9`.

| Existing boundary | Go coverage or next owner |
| --- | --- |
| Protocol/claim and HTTP cases in `runner/tests/run.php`; server positive/negative corpus | `internal/protocol` strict/schema/HTTP tests and optional wire parity |
| CLI arguments and setup bundle fields in `SetupTest.php` | `internal/command` parser and no-side-effect refusal tests; operational exit behavior belongs to supervision/profile/installer slices |
| Supervisor/watchdog, `SourceArchiveTest.php`, `AttemptStateStore.php` | `internal/supervisor`, `internal/sandbox`, `internal/workspace`, and `internal/attemptstate`: fenced fixture execution, independent process cleanup, strict extraction, and the unversioned attempt JSON |
| Profile/home/container/exclusion tests and `Profiles/ProfileStore.php` | `internal/profile` ports locked `active`, `pending`, `completed`, and `execution` journals (16 KiB read bound), protected homes, PHP-state recovery, native authentication policy and credential-container lifecycle; repository execution exclusion is activated with the Codex driver slice |
| Codex driver/event/transport/supervisor tests and `Drivers/AgentSessionStore.php` | `internal/codex`, `internal/codexsession`, `internal/supervisor` and `internal/command`: strict native protocol, protected run-keyed sessions, three-container isolation, fenced command mediation, verified patches and composite watchdog cleanup |
| Package/setup/release tests | Packaging slice: verified compiled artifacts, platform execution tests, state-preserving installation and rollback |

The fixture supervisor reads the unversioned `active-attempt.json` journal and holds an exclusive host lock for its lifetime. It preserves nullable IDs and accepts canonical UTC `Z` and PHP `DATE_ATOM` timestamps, including nonzero host-timezone offsets. Reads preserve the timestamp's instant without rewriting the journal; subsequent Go saves normalize to UTC `+00:00`. Unknown or malformed state is retained, not overwritten. Recovery accepts only its exact attempt workspace and verifies container ownership before deletion; unsupported legacy/profile-backed container ownership requires recovery with the matching PHP installation, not forced deletion or a replacement claim. Profile and native session journals remain untouched until their owning migration slices are implemented.

Claims are persisted before preparation. A deterministic container name is journaled and an independent watchdog acknowledges the creation phase before Docker creation begins. After creation, the watchdog acknowledges the immutable container ID before that ID replaces the journal reservation; execution starts only after both steps succeed. This ordering lets a restarted supervisor safely reconcile a confirmed ID without leaving the old watchdog waiting for an unknown container.

A name-only reservation after a crash requires manual recovery, even when Docker currently reports no matching container: temporary absence cannot rule out a late daemon-side create. A fresh supervisor retains that journal and refuses replacement claims or a stopped acknowledgement. The old watchdog remains responsible for removing any late owned container. A crash after the watchdog learns the ID but before the journal is updated can also require manual recovery; this deliberately favors retained evidence over an unsafe automatic acknowledgement. Never delete a retained journal just to resume polling.

HTTP calls retain the PHP baseline's five-second total timeout. Heartbeats run independently throughout preparation, execution and publication, on a ten-second cadence with a forty-five-second lease and the immutable overall deadline. Revoked execution cancels downloads and commands, but cannot cancel mandatory cleanup. Completion is reported to the operator only after container/workspace removal, a fenced stopped acknowledgement and journal clearance. Native profile operations use the same cadence and a fifteen-minute overall bound, retain ambiguous create/completion state for recovery, and acknowledge completion only after credential-container cleanup. Repository-native execution, service installation and release packaging remain separate migration work.

Docker preflight, lifecycle commands and the independent watchdog share the host's Docker client configuration (`HOME`, `DOCKER_HOST`, `DOCKER_CONTEXT`, `DOCKER_CONFIG`, `DOCKER_CERT_PATH`, and `DOCKER_TLS_VERIFY`). Provider and control-plane credential variables are excluded. This configuration belongs only to trusted host-side Docker clients; it is not injected into repository containers. Container creation explicitly clears all upper/lowercase proxy variables so Docker's client-config defaults cannot inject credential-bearing proxy URLs. Keep the selected Docker endpoint and context stable while an attempt or its recovery journal exists.

`make go-check` needs neither PHP nor the private server. The `make go-parity-check` target compares claim identities and the actual PHP and Go wire requests for claims, heartbeats, stopped acknowledgements, events, artifact upload/download, completion, and profile operations using synthetic data and an in-memory transport. Its PHP oracle is excluded from default Go tests by the `phpbaseline` build tag.

During the transition, `make check` also runs that parity check, `make go-runtime-check`, and the existing PHP runner, packaging and native-container fixtures against synthetic accounts. `go-runtime-check` builds the watchdog and exercises the Go Docker lifecycle, supervisor parent-death cleanup, and the complete HTTP-to-supervisor fixture path. It requires PHP 8.5, a Linux Docker engine and the deliberately acquired fixture image described in the repository README. Those existing tests remain the behavioral reference until their Go equivalents and the separate live validation gates pass.


## Review snapshots

Go Codex review execution requires both ordered source archives from the claim: base at `/baseline` and head at `/workspace`. Workspace preparation verifies their artifact hashes and revisions before the executor retains both directory identities. Implement and fix runs require one head archive. A missing or invalid review snapshot fails execution instead of silently reviewing only the head.

The two review snapshots occupy disjoint subdirectories of the attempt memory volume, bounded at 512 MiB for reviews to hold both 128 MiB input limits plus synthetic Git objects and metadata. Single-source runs retain their 256 MiB volume limit; per-container CPU, memory, and PID limits remain unchanged. Docker mounts the base subdirectory read-only and the head subdirectory writable, without exposing their parent. Setup and runner startup require both Docker client and Linux engine 26.0 or newer, which introduced [`volume-subpath` mounts](https://docs.docker.com/engine/release-notes/26.0/#2600). Unsupported clients or engines fail preflight with a specific requirement before configuration activation or work is claimed. The temporary snapshot writer is removed before repository tools are enabled. The local Git commit records the supplied head for edit collection; it is not pull-request history. Reviews compare `/baseline`, which holds the server's `diff_base_sha` merge-base snapshot, with `/workspace`, which holds `head_sha`, including added and deleted files. `target_sha` is carried for freshness only and is never downloaded.

The standalone `make check` gate includes a credential-free regression through the shipped repository MCP server, Go bridge/mediator, and real Docker repository. After the native fixture image has been built by the gate, rerun it locally with:

```sh
SHIPMUNK_CODEX_DOCKER_TEST=1 go test -race -count=1 -v ./internal/codex -run TestDockerReviewSnapshotsThroughRepositoryMCP
```

The test derives the changed-file set from distinct source contents, attempts baseline writes through direct and process/symlink paths, checks writable head behavior, and confirms cleanup. It establishes repository tool and isolation behavior using synthetic snapshots, not provider-account compatibility.
