# Live sandbox and native credential isolation

Use a dedicated Linux execution host, designated Codex and Claude Code accounts, and disposable private repositories containing adversarial fixtures. Do not use personal credentials or reuse a general-purpose workstation as the runner host.

1. Authenticate each native runtime through the operator-controlled runner profile flow. Record the runner image, container runtime, kernel and native runtime versions without recording tokens, refresh credentials or credential-file contents.
2. Claim one review with each provider and verify the selected profile credential works inside its separately scoped native-runtime boundary. Confirm there is no fallback to an API key or to another profile when authentication fails.
3. Run repository fixtures that inspect environment variables, mounts, process arguments, writable paths, procfs and common credential locations. Confirm they cannot read the runner bearer token, callback metadata, Laravel environment, APP_KEY, GitHub credentials or another profile's native credentials.
4. Exercise absolute paths, traversal entries, symlinks, hard links, device entries, oversized archives and hash mismatches. Confirm extraction fails before native execution and cannot write outside the disposable workspace.
5. Attempt metadata, loopback, private-control and peer-workload network access. Confirm the configured egress policy fails closed, and verify CPU, memory, PID, disk, wall-time, non-root, dropped-capability and no-new-privileges controls from inside the sandbox.
6. Inspect the host after each run. Confirm the container, writable layers, workspace and transient credential material are removed while durable server evidence contains only sanitized events and artifact metadata.

Record exact commands and observed results using designated resource identifiers only. Fake native executables and local fixture credentials used by `make runner-check` do not satisfy this scenario.

## Credential lifecycle checks

Run the login/status portions of [RT-01](RT-01.md) and [RT-02](RT-02.md), then exercise the available Codex repository adapter and record each result independently. Inspect each credential container with `docker inspect`: one profile home, no repository or control-plane mount, a non-root user, read-only root, dropped capabilities, no-new-privileges and disabled container logging. Run the other profile's lookup and symlink fixtures through `make runner-check`; those synthetic tests do not replace live assertions.

The credential-only login container has outbound networking for official authentication. This does not enable network access for repository sandboxes and does not establish the provider-specific egress policy required by the execution adapters.
